# E-portfolio requirements from the school brief

Source: [Professional Networking draaiboek 2026–27](../Professional_Networking_Draaiboek_2026-27.pdf), section 3.3 (page 4), section 4 (pages 9–10), and the website-only checklist referenced by section 4.3 (item 1, page 5).

Scope is limited to the e-portfolio, as requested by the owner. This document does not summarize the rest of the module or claim that its assignments have been completed. Any future school changes or exact deadlines must be checked in LEHO.

## Requirements and site response

| Requirement | Planned response |
| --- | --- |
| Professional portfolio lets another IT professional understand interests, abilities, and motivations | Home and About describe Kobe's specific engineering interests and capabilities, with honest student-level wording |
| Website is available at a public URL | Static Astro site hosted on GitHub Pages |
| Owner is clearly identifiable through About | Name, concise introduction, interests, skills, and public profile links |
| A post explains how the website was made | Activity entry about the stack, content workflow, hosting, and domain choice |
| Relevant articles can be found quickly | Activity is the article overview; the owner declined a separate school overview |
| Event articles offer meaningful reflection | Reusable article layout with context, learning, critique, and future relevance |
| Submit the URL initially and a PDF at the final deadline | Provide a full-site snapshot the owner can export and submit; exact deadlines are not given in these sections |

The brief explicitly permits GitHub/GitLab Pages, static site generators, and custom sites. Buying a domain or hosting is not required. It also advises keeping setup effort reasonable and publishing an initial version early.

## Reflection guidance

Section 4.3 does not impose a universal article word count. It recommends a useful balance of detail, and suggests addressing:

- Event frequency, duration, audience, and speaker background.
- Technical depth and what was learned, including useful negative experiences.
- Relationship to prior learning and suggestions for the organizers or programme.
- Whether the topic deserves further exploration.
- Whether the writer would attend again or recommend it, and why.

This is general article guidance. It must not be used to override any activity-specific rules the owner later wants to map into the site.

## PDF scope

Section 4.4 requires a PDF version to preserve the submission if hosting fails. It allows straightforward browser Save as PDF or Markdown conversion and does not require a separately designed document.

The owner's additional preference is that the PDF looks like the screen. Reuse the site's typography and content, with print adjustments for legibility and page breaks. A combined printable page is a suitable starting point; automated downloads remain an implementation option.

## Optional content

Section 3.3 gives CVs, projects, repositories, extracurricular work, and experience as examples the student may include. They are not a requirement to publish an employment or education timeline. The current site therefore does not need featured projects or substantial résumé sections.

## Out of scope for this summary

Detailed podcast, hackathon, LinkedIn, TI on STAGE, application dossier, and whole-module assessment requirements. Add only the article/evidence mappings the owner later confirms are needed on the website; do not create unrelated submission or outreach workflows.
